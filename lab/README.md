# Порядок виконання та здачі лабораторних робіт

## 1. Загальні вимоги

Для виконання лабораторних робіт необхідно створити **один GitHub-репозиторій** для всіх лабораторних робіт з дисципліни.

Основна гілка репозиторію:

```text
main
```

Для репозиторію необхідно увімкнути **GitHub Pages**, щоб результати лабораторних робіт можна було переглядати безпосередньо у браузері.

Приклад:

```text
https://username.github.io/web-programming/
```

---

## 2. Структура репозиторію

У кореневій папці репозиторію повинен знаходитися файл:

```text
index.html
```

Він виконує роль головної сторінки та містить посилання на всі виконані лабораторні роботи.

Рекомендована структура:

```text
web-programming/
│
├── index.html
│
├── lab_1/
│   ├── index.html
│   ├── style.css
│   ├── report.md
│   └── screenshot.png
│
├── lab_2/
│   ├── index.html
│   ├── style.css
│   ├── script.js
│   ├── report.md
│   └── screenshot.png
│
├── lab_3/
│   └── ...
│
└── README.md
```

Для кожної лабораторної роботи необхідно створювати **окрему папку**:

```text
lab_1
lab_2
lab_3
...
```

Назви папок повинні бути зрозумілими та відповідати номеру лабораторної роботи.

---

## 3. Головна сторінка `index.html`

Головна сторінка репозиторію повинна містити список виконаних лабораторних робіт із посиланнями на відповідні папки.

Наприклад:

```html
<h1>Лабораторні роботи з Web-програмування</h1>

<ul>
    <li>
        <a href="./lab_1/">Лабораторна робота №1</a>
    </li>

    <li>
        <a href="./lab_2/">Лабораторна робота №2</a>
    </li>

    <li>
        <a href="./lab_3/">Лабораторна робота №3</a>
    </li>
</ul>
```

Після публікації через GitHub Pages лабораторні роботи повинні бути доступні за адресами приблизно такого вигляду:

```text
https://username.github.io/web-programming/lab_1/
https://username.github.io/web-programming/lab_2/
```

---

## 4. Вміст папки лабораторної роботи

У папці кожної лабораторної роботи повинні знаходитися:

* файли з програмним кодом лабораторної роботи;
* файл звіту;
* скріншот результату виконання роботи.

Звіт можна оформити у форматі:

```text
report.md
```

або

```text
report.docx
```

### **------------->>>>>>> Наприклад: [Переглянути звіт](./report.md) <<<<<<<<-------------**

Рекомендовано використовувати формат **Markdown (`.md`)**.

---

## 5. Вимоги до звіту

Звіт повинен бути коротким — **не більше 3 сторінок А4**.

У звіті необхідно вказати:

### 1. Назва лабораторної роботи

Наприклад:

```text
Лабораторна робота №1
Створення семантичної HTML-сторінки
```

### 2. Мета роботи

Коротко описати, які технології або можливості потрібно було опрацювати.

Наприклад:

> Мета роботи — ознайомитися зі структурою HTML-документа та навчитися використовувати семантичні HTML-теги.

### 3. Що було реалізовано

Коротко описати виконану роботу.

Наприклад:

* створено HTML-сторінку;
* використано семантичні теги;
* додано зображення та посилання;
* створено форму;
* сторінку опубліковано через GitHub Pages.

### 4. Результат роботи

Додати **1–2 скріншоти** готової сторінки або результату виконання програми.

Наприклад:

```md
![Результат виконання лабораторної роботи](./screenshot.png)
```

### 5. Висновок

1–3 речення про те, що було вивчено або закріплено під час виконання роботи.

Наприклад:

> У результаті виконання лабораторної роботи було закріплено навички створення HTML-сторінок та використання семантичних тегів.

---

## 6. Вимоги до програмного коду

Код повинен:

* відповідати завданню лабораторної роботи;
* бути структурованим і зрозумілим;
* не містити непотрібних файлів;
* коректно працювати після відкриття через GitHub Pages;
* використовувати відносні шляхи до CSS, JavaScript, зображень та інших ресурсів.

Наприклад:

```html
<link rel="stylesheet" href="./style.css">
<script src="./script.js"></script>
```

Не рекомендується використовувати локальні шляхи виду:

```text
/Users/student/Desktop/project/image.png
C:\Users\Student\Desktop\...
```

оскільки вони не працюватимуть на GitHub Pages.

---

## 7. GitHub Pages

Для публікації робіт необхідно:

1. Відкрити GitHub-репозиторій.
2. Перейти у:

```text
Settings → Pages
```

3. У розділі **Build and deployment** вибрати:

```text
Deploy from a branch
```

4. Вибрати:

```text
Branch: main
Folder: /(root)
```

5. Зберегти налаштування.

Після публікації перевірити, що:

* відкривається головна сторінка;
* працюють посилання на лабораторні роботи;
* відкривається кожна лабораторна робота;
* завантажуються стилі, JavaScript та зображення.

---

## 8. Що потрібно здати в Classroom

Для здачі **кожної лабораторної роботи** в Classroom необхідно додати **два посилання**.

### 1. Посилання на GitHub-репозиторій

Наприклад:

```text
https://github.com/username/web-programming
```

### 2. Посилання на відповідну лабораторну роботу в GitHub Pages

Наприклад для лабораторної №1:

```text
https://username.github.io/web-programming/lab_1/
```

Таким чином викладач повинен мати можливість:

* переглянути вихідний код у GitHub;
* відкрити готовий результат через GitHub Pages;
* переглянути короткий звіт у папці відповідної лабораторної роботи.

---

## 9. Перед здачею перевірте

* Репозиторій доступний для перегляду.
* Усі зміни завантажені на GitHub.
* GitHub Pages працює.
* `index.html` містить посилання на всі виконані роботи.
* Для лабораторної створена окрема папка `lab_N`.
* У папці є вихідний код.
* У папці є `report.md` або `report.docx`.
* У звіті є мета, опис виконаної роботи, скріншот та короткий висновок.
* Посилання, додані в Classroom, відкриваються без помилок.
